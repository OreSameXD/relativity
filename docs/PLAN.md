**Ключевое решение — три независимых острова на главной, связанных через один store:**

1. Текст глав — обычный HTML из Astro (нулевой JS, индексируется, работает без WebGL).
2. UI интерактивов — маленькие React-острова (`client:visible`), пишут в store.
3. Сцена — один остров `<StoryCanvas client:only="react">` с `position: fixed` на весь экран, читает store в `useFrame`.

Острова Astro делят ES-модули, поэтому `store.ts` (zustand vanilla) — общий синглтон без React-контекста. Контроллер скролла (`scroll.ts`) — тоже vanilla, подключается в `index.astro` через `<script>`. Так сцена ничего не знает о скролле, а скролл — о Three.

## 3. Камера по скроллу

### 3.1. Высота страницы
Каждая глава — `<section data-chapter="N">` высотой `var(--chapter-h)`: интро 150vh, интерактивные главы 220vh, финал 120vh. Итого ≈ 14 экранов. Canvas фиксирован, пин ScrollTrigger не нужен (ничего не пинится, значит нет reflow и проблем на мобильных).

### 3.2. Мастер-таймлайн
Один GSAP-таймлайн на весь `#story`:

```ts
const tl = gsap.timeline({
  scrollTrigger: {
    trigger: '#story', start: 'top top', end: 'bottom bottom',
    scrub: 0.8,
    snap: { snapTo: 'labels', duration: { min: 0.3, max: 0.9 }, delay: 0.15, ease: 'power2.inOut' },
  },
});
```

Для каждой главы N из `chapters.ts`:
- **перелёт** (длительность 1): твин `cam.t` от якоря N−1 к N с `power2.inOut`, твин `cam.look` к цели взгляда главы, параллельно fade-out текста предыдущей главы;
- метка `chN`;
- **удержание** (длительность 1.5): камера стоит, появляется текст и UI (`y: 24 → 0, opacity`), в store `chapter = N`.

Snap на метки даёт «кадры фильма»: после остановки скролла страница сама доезжает до главы, интерактив оказывается ровно в кадре.

### 3.3. Что делает камера с `cam.t`
- Якоря глав лежат на `CatmullRomCurve3`; `curve.getPoint(t)` проходит через якорь N при `t = N/6`. Твин `t` между соседними якорями = полёт по дуге, а не по прямой.
- Положение = точка кривой + лёгкий «дыхательный» дрейф (sin по времени, амплитуда ≈ 0.05) + параллакс от мыши (≈ 0.3 единицы, lerp).
- `lookAt` лерпится к `cam.look`; FOV слегка расширяется в перелёте (55 → 62 → 55) — ощущение скорости.
- На перелёте ускоряется звёздная пыль вокруг камеры (стример-эффект), в удержании она почти стоит.

Все главы физически расположены вдоль кривой в одной сцене, расстояние между якорями ≈ 40 единиц. Это и есть «одна непрерывная сцена»: камера реально летит от световых часов к близнецам, потом к сетке и т.д.

### 3.4. Lenis
Lenis двигает нативный скролл, поэтому `scrollerProxy` не нужен:
```ts
lenis.on('scroll', ScrollTrigger.update);
gsap.ticker.add(t => lenis.raf(t * 1000));
gsap.ticker.lagSmoothing(0);
```
Риск: snap ScrollTrigger делает `window.scrollTo`, Lenis может с ним спорить. Проверяется в прототипе; запасной вариант — свой snap через `lenis.scrollTo(ближайшая метка)` по окончании скролла (`velocity ≈ 0`).

### 3.5. prefers-reduced-motion
`gsap.matchMedia()`: в ветке reduce мастер-таймлайн не создаётся. Вместо него на каждую секцию — `ScrollTrigger.create({ onToggle })`: затемнение канваса 200 мс, камера ставится в якорь главы, затемнение снимается; текст просто появляется. Lenis выключен, дрейф и параллакс выключены. Интерактивы работают как обычно.

## 4. Переходы и загрузка глав

- В store хранится `chapter` (активная) и `cam.t`. Группа главы N монтируется, когда `|t·6 − N| ≤ 1.2` (то есть за один перелёт до неё), и размонтируется, когда камера улетела дальше чем на 1.5 главы. Так в памяти не больше трёх глав, а шейдеры успевают скомпилироваться до входа в кадр.
- Каждая группа — `React.lazy` + `<Suspense fallback={null}>`: код главы приезжает отдельным чанком.
- Текст главы живёт в DOM и анимируется тем же таймлайном, поэтому текст и 3D всегда синхронны.
- Переход «удержание → перелёт»: текст уходит вверх с fade, UI интерактива скрывается; на перелёте bloom чуть усиливается, DoF фокус переезжает на новую цель.

### Постобработка
`EffectComposer multisampling={0}` → `Bloom(mipmapBlur, threshold 1.0)` → `LensingEffect` (только в главе 4, в остальных `strength = 0`, эффект отключён) → `DepthOfField` (десктоп) → `Noise(0.04)` → `Vignette` → `ToneMapping(ACES)`.

### Качество и FPS
Уровни `high | medium | low` в store.
- Старт: `pointer: coarse` или ширина < 768 → `medium` (DPR ≤ 1.5, без DoF, частиц в 3 раза меньше); иначе `high` (DPR ≤ 2).
- `PerformanceMonitor` из drei: при падении ниже 30 FPS → понижение уровня (`low`: DPR 1, без bloom-mipmap, минимум частиц, сетка 64×64 вместо 192×192). Подъём обратно — только после 10 с стабильных 55+ FPS.
- Без WebGL (`canvas.getContext('webgl2')` вернул null) — остров сцены не монтируется, в секциях показываются `public/fallback/ch-N.jpg` с подписью. Кадры снимаются с реальной сцены через dev-страницу `/__shot?chapter=N`.

## 6. Статьи

### 6.1. Коллекция
`src/content/config.ts`:
```ts
articles: { title, description, order, chapter, phenomenon, ogTitle?, updated }
```
Шесть файлов в `src/content/articles/`: `intro-sr-gr`, `time-dilation`, `twin-paradox`, `curved-spacetime`, `gravitational-lensing`, `gps`. Порядок — по `order`; prev/next считаются из коллекции.

### 6.2. Макет `Article.astro`
- Колонка текста `max-width: 70ch`, слева на десктопе (≥ 1100 px) — липкое оглавление из `headings` рендера MDX; на мобильных — свернутый список сверху.
- Шапка: тема, короткая «суть» (lead), ссылка «← назад к истории» (ведёт на `/#ch-N`, история доезжает до главы по хэшу через `lenis.scrollTo`).
- Низ: карточка «Следующее явление →» и «← Назад к истории».
- 3D только в блоке интерактива: остров `client:visible`, `frameloop="demand"`, свой маленький Canvas, без постобработки (или только Bloom).

### 6.3. Формулы
`remark-math` + `rehype-katex` на сборке, на клиенте KaTeX не грузится. Шаблон блока в MDX:

```mdx
<Formula id="einstein-radius">
$$\theta_E = \sqrt{\frac{4GM}{c^2}\,\frac{D_{LS}}{D_L D_S}}$$
<Legend>
- θ_E — угловой радиус кольца Эйнштейна
- G — гравитационная постоянная, 6,674·10⁻¹¹ м³·кг⁻¹·с⁻²
- …
</Legend>
<Example>
Для M = 10¹² M☉, D_L = 1 Гпк … θ_E ≈ 1,5″ (подстановка с числами)
</Example>
</Formula>
```

Живая связь интерактива с формулой: в KaTeX включается `trust` для `\htmlClass`, в подстановке помечаются слоты `\htmlClass{slot-v}{0{,}6c}`. Интерактив меняет `textContent` этих span-ов — формула «пересчитывается» без клиентского KaTeX.

### 6.4. Разделы каждой статьи (по брифу)
1. Суть — 2–3 предложения.
2. Как открыли — кто, когда, с источником.
3. Формулы — блоки по шаблону выше.
4. Интерактив — остров, связан со слотами формулы.
5. Интересные факты — 3–5, каждый со сноской.
6. Источники — `<Sources>`: учебники, NASA, ESA, статьи; в тексте сноски `[1]`.

Пометки: `<Simplified>` — мелкий текст «упрощено» рядом с визуализацией; факты, которые не удалось подтвердить, помечаются «требует проверки» и собираются в отчёт этапа.

`Base.astro`: `title`, `description`, canonical, `og:image` → `/og/[slug].png` (satori, шрифт Unbounded с кириллицей, тёмный фон, заголовок + подзаголовок), `twitter:card`. Для главной — своя OG-картинка. Sitemap через `@astrojs/sitemap`.

## 8. Точность: что буду проверять по источникам
- Световые часы, γ, близнецы — Тейлор, Уилер «Физика пространства-времени»; Ландау, Лифшиц т. II.
- Линза: Einstein 1936 (Science), Walsh et al. 1979 (первая линза Q0957+561), NASA/ESA Hubble (Einstein Cross, кольца).
- GPS: Ashby N. «Relativity in the Global Positioning System», Living Rev. Relativity 6 (2003) — цифры +45/−7/+38 мкс; цифра «≈10 км/сутки» — популярная оценка (Pogge, OSU), в статье укажу как оценку с источником или помечу «требует проверки».
- Кривизна: Eddington 1919 (Dyson, Eddington, Davidson 1920), Gravity Probe B (NASA).

Всё, что в сцене нарисовано приближённо (прогиб сетки, тонкая линза, мгновенный разворот близнеца, масштаб орбит GPS), помечается «упрощено».
